# Проверка Бзикер 2.0

Применяй только для выбранного профиля В, без повторного выбора. Найди корень по `AGENTS.md`, `docs/ARCHITECTURE.md` и `game/`. Прочитай архитектуру, актуальный план и `game/README-PHASER.md`. Соседний исходный Bziker, рабочая пользовательская БД и секреты не участвуют в тестах. Пути и команды ниже относительны корню или явно указанному `game/`.

## Выполнить проверки

Сначала узнай точный предмет проверки и изменённые пути; сопоставь ожидаемое поведение с действующими тестами. Запусти применимые существующие помощники `tools/` по их реальной справке. Проверяй stdout/stderr и exit code; отсутствие нужного runtime или зависимости означает «не выполнено» с причиной. Не превращай отсутствие тестов в PASS.

Основные команды из корня: `python3 tools/check-project.py --quick` проверяет core и инструменты, `python3 tools/check-project.py --full` — весь Python/Node регресс игры. `python3 tools/check-project.py --materials` добавляет полную SHA-проверку библиотеки. Выбирай охват по задаче и фиксируй конкретные флаги; quick не объявляй полной проверкой.

Для диагностики или проверки исходной передачи остаются доступными команды из `game/`:

```sh
python3 scripts/check-handoff.py
python3 -m unittest discover -s tests -v
node scripts/test-node.mjs
```

JavaScript требует Node 22+ и локальные зависимости; при необходимости `npm ci --ignore-scripts` в `game/`. Узкая проверка изменения может ограничиваться затронутыми тестами с явным указанием охвата; заявления о полном регрессе требуют полного запуска. Сохраняй фактические логи в `verification/`; старый лог не подтверждает текущую сборку.

Для локальной QA из корня используй `python3 tools/run.py --port 8796 --demo --db verification/qa.sqlite3` с отдельной тестовой БД; игра доступна на `http://127.0.0.1:8796/`, лаборатория — `/character-lab`. Помощник привязывает demo к `127.0.0.1`; его параметры сверяй через `--help`. Прямой диагностический вариант с отдельной тестовой БД из `game/`:

```sh
AUTH_MODE=demo HOST=127.0.0.1 python3 server.py --port 8791 --db ../verification/qa.sqlite3
```

Выбирай незанятый порт и отдельную тестовую БД. Не переиспользуй существующий файл без проверки его назначения. Открой соответствующий локальный URL доступным браузерным инструментом. Наличие HTTP 200 не доказывает запуск Phaser или работу игры.

## Пройти пользовательские сценарии

На запущенной игре проверь фактические действия и результат состояния. Выбирай связанные с изменением сценарии; полный приёмочный отчёт требует всех применимых пунктов:

- Вход/повторный вход и сохранение прогресса. Движение во всех направлениях, остановка и столкновения; наблюдай перемещение персонажа в мире, а не только реакцию кнопки. Проверь двери и переходы внутрь/наружу, соразмерность интерьера и ограничения доступа.
- Джойстик и три кнопки в размере телефона, зеркальная раскладка для левой руки, отсутствие перекрытий управления. Отдельный инвентарь на 10 слотов, телефон с общением/заданиями, открытие/закрытие и восстановление управления.
- Реальное получение/выбор предмета и надевание комплекта, в том числе при движении и смене направления. Все слои сохраняют один pose key/фазу/опору, нет смены пола/масштаба или разрыва кадра. Неполный комплект отклоняется целиком. Проверь доступные предметы в руке и сидение; телефон сохраняет сидячую позу и занятое место.
- Для затронутых экономических и социальных функций проверь серверное состояние: кошелёк/награда/покупка/клановые права не меняются лишь от поддельного клиентского события. Существующие казино и другие комнаты используют игровую валюту. Несвязанные подсистемы не объявляй проверенными по одному открытию страницы.

Фиксируй воспроизводимые шаги, ожидаемое и наблюдаемое поведение, viewport, браузер и ошибки console/network. Скриншот фиксирует состояние, а не весь сценарий. Если браузер недоступен, запиши «браузерный сценарий не выполнен»; unit tests не заменяют эту проверку.

## Отдельно оценить артефакты

Если проверяешь перенос, из корня выполни `python3 tools/verify-materials.py --dest .`: он сверяет реальные байты по сохранённому manifest без обязательного доступа к исходнику. Дополнительное сравнение с внешним источником требует его фактической доступности и параметров из текущего `--help`; не заявляй неизменность внешнего источника по проверке одной копии. `verification/materials-verification.json` — подтверждение целостности, не качества. Импортёр не перезапускай поверх готовой непустой библиотеки ради проверки.

По `$bziker-character-pipeline` сверь определения, отдельные PNG, фиксированный холст/опору, полное покрытие поз и слотов, порядок по направлениям, hand/seating points и один clock. Проверь также загрузку новых definition/resources через `game/web/character-system/asset-loader.js`; для approved требуется artReview со свидетельством художественного просмотра. Сверь canonical master, лицо/голову/палитру и непрерывность настоящей походки. Прямоугольные сдвиги/зеркалирование и колебание цельного спрайта не принимаются за исправленный шаг. Отчёт о количестве ресурсов и SHA-256 подтверждает целостность, но не художественную приёмку.

Для мебели нужны четыре нарисованных объёмных вида; повтор/зеркало одного PNG не доказывает четыре ракурса. Драфты не объявляй одобренными по техническому PASS.

## Записать вывод

В `verification/` сохрани один относящийся к запросу отчёт с командами/exit codes, результатами сценариев и ссылками на доказательства. Различай «пройдено», «не пройдено» и «не выполнено» с причиной. Отдельно укажи охват логики, целостности, совместимости кадров, художественного просмотра, браузерного viewport и физического телефона. Эмуляция viewport не подтверждает касания, WebGL, звук и производительность реального устройства. Если физического телефона не было, это остаётся невыполненной проверкой.

Исправляй локальные обнаруженные дефекты в разрешённой задаче и повторяй затронутые проверки. Успешные технические проверки не дают автоматического художественного одобрения и не означают завершение всей игры. Публикация, внешние сообщения и реальные платежи не входят в приёмку.
