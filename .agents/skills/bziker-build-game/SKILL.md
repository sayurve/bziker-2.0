# Разработка Бзикер 2.0

Работай только для выбранного профиля В. Если профиль уже выбран, не спрашивай повторно. Корень проекта — ближайший родитель с `AGENTS.md`, `docs/ARCHITECTURE.md` и `game/`; все команды ниже относительно него. Прочитай эти документы и относящийся к запросу участок `docs/IMPLEMENTATION_PLAN.md`. Уточняй только существенные недостающие требования; обычные локальные исправления и проверки уже разрешены.

## Выбрать точку изменения

Сначала проследи существующий путь действия от интерфейса к серверу и сохранению. `game/README-PHASER.md`, `game/package.json` и текущие тесты объясняют запуск и зависимости. Рендер — `game/web/phaser-world-renderer.js` и `phaser-scene-paint.js`, движение/состояние — `game/web/world.js`, исходные актёры — `game/web/source-actors.js`; Python-модули рядом с `game/server.py` владеют правилами. Проверяй актуальные экспортируемые функции перед вызовом.

Сохраняй действующие аккаунты, прогресс, экономику, задания, общение, кланы, карточные комнаты, казино и викторину при изменении их связей. Соседний исходный Bziker не менять. Не переносить действующую пользовательскую БД и секреты. Копия материалов — `materials/Bziker/`; исторический пример не становится функцией игры лишь от копирования.

## Реализация

- Сохраняй Phaser как движок сцены и Python как авторитет для движения, коллизий, действий, кошельков, наград, покупок, кланов и доступа в помещения. Клиентская анимация и событие её завершения не выдают деньги и права. Проверяй отказ при недопустимом запросе, а не только успешный UI.
- Основная компоновка — телефон: джойстик, три кнопки действия/инвентаря/телефона и зеркальная раскладка для левой руки. Инвентарь — отдельные 10 слотов; телефон обслуживает общение и задания. Сохраняй работу сидения и занятое место при открытии телефона.
- Мир состоит из самостоятельных объектов, коллизий, точек взаимодействия и посадки. Дороги с перекрёстками, парковки и подходы связаны с домами. Полный экран референса не заменяет эти объекты. Интерьеры соразмерны персонажу; мебель требует четырёх настоящих объёмных видов с общей перспективой и материалами.
- Для поз/гардероба следуй `$bziker-character-pipeline` и текущему контракту `game/web/character-system/`. Один snapshot задаёт всем слоям позу, направление и фазу. Смена одежды атомарна, без изменения масштаба, опоры, физики и фазы. Сохраняй явно названный `legacy-composite`, пока новые раздельные слои отсутствуют.
- Работай с закреплённым движком в `game/web/vendor/`; не обновляй Phaser или зависимости без причины в запросе. Растровые рисунки создавай/редактируй через доступный встроенный image_gen; кодовые и векторные мастера — в исходном формате. Наличие image_gen не подтверждает одинаковое лицо в разных кадрах.

Перед изменением зафиксируй проверяемый сценарий и ожидаемое поведение. Добавляй существенные регрессионные тесты логики; не заменяй ими запуск игры. Используй существующие помощники `tools/` по их справке, не придумывай CLI и не переписывай помощник внутри навыка. Если помощник отсутствует, укажи это и выполни применимую существующую проверку.

## Подтверждение изменения

Основные команды из корня: `python3 tools/run.py --port 8796 --demo` запускает локальную игру на `127.0.0.1`; `python3 tools/check-project.py --quick` проверяет core и инструменты; `python3 tools/check-project.py --full` выполняет Python/Node регресс всей игры. `python3 tools/check-project.py --materials` дополнительно сверяет SHA материалов; применяй его при изменении или передаче библиотеки. Для новых моделей лаборатория — `http://127.0.0.1:8796/character-lab`; её код — `game/web/character-lab.js`.

Для узких или диагностических запусков из `game/` используй соответствующие тесты; общий JavaScript runner — `node scripts/test-node.mjs`, Python — `python3 -m unittest discover -s tests -v`. Нужны Node 22+ и локальные зависимости `game/package-lock.json`; при отсутствии установи их `npm ci --ignore-scripts` в `game/`. При изменении запуска/пакета выполни также `python3 scripts/check-handoff.py`.

Для затронутого игрового поведения проведи сценарий в реальном браузере через `$bziker-game-qa`. Отчёт в `verification/` должен назвать команды, exit code, наблюдения и ещё не проверенные условия. Структурный PASS, скриншот и список файлов не доказывают художественное качество, работу на физическом телефоне или завершение всей игры. Локальная задача не разрешает публикацию, внешние сообщения или реальные платежи.
