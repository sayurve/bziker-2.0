# Размещение Бзикера на сервере

## Поддерживаемый вариант

Текущий HTTP-сервер поддерживает два режима: `demo` на локальном интерфейсе и `telegram` для HTTPS-сайта Telegram Mini App. Обычный публичный режим с одним логином и паролем пока не выделен; `AUTH_MODE=account` не существует. Документ сохраняет этот контракт и не обходит запрет публикации локального режима.

Для публичного варианта нужны сервер с Python 3.10+, домен, HTTPS-прокси, Telegram-бот и его токен. Сервер игры использует SQLite; запускайте один экземпляр процесса с одной БД. Каталог БД должен сохраняться при обновлении кода. Нагрузочный предел проверяют отдельно в целевой среде.

## Установка оператором

1. Разместите экспортированную папку проекта в `/opt/bziker` и выполните `python3 scripts/check-handoff.py`.
2. Создайте отдельного системного пользователя `bziker` и доступный ему каталог `/var/lib/bziker`.
3. Создайте `/etc/bziker/bziker.env` с правами чтения только оператора/службы:

```dotenv
AUTH_MODE=telegram
HOST=127.0.0.1
PORT=8791
PUBLIC_URL=https://game.example.com
BOT_TOKEN=replace-with-real-token-outside-git
```

4. Замените домен на собственный. `PUBLIC_URL` должен указывать на корень HTTPS-сайта, без пути, query или fragment. Токен не добавляют в GitHub или архив.
5. Скопируйте шаблон `deploy/bziker.service` в systemd. Проверьте путь к Python и каталог кода на целевом сервере. После установки запустите службу штатными средствами systemd.
6. Настройте TLS-прокси, используя `deploy/nginx.conf.example`. В шаблоне замените домен и пути существующих сертификатов. Прокси передаёт канонический `Host`, совпадающий с `PUBLIC_URL`; запросы API с другим `Host` или `Origin` сервер отклоняет. Статические файлы также передаются сервером игры, который сохраняет явный список разрешённых ресурсов.

## Проверка перед выдачей ссылки

Проверьте загрузку страницы и всех её модулей по HTTPS, запуск Mini App из Telegram, регистрацию, повторный вход с тем же прогрессом, перемещение, вход и выход из интерьера, инвентарь и телефон. Служебные файлы, `.env` и БД должны отвечать 404. На публичном сайте сессия имеет `HttpOnly`, `SameSite=Strict` и `Secure`; изменение состояния требует сессии, корректного Origin и CSRF.

Простой запрос `/api/bootstrap` создаёт сессию и не является безвредным healthcheck для рабочей БД. Для контроля доступности используйте `GET /`, не API. Пример запускающего бота `bot.py` выполняет реальные Telegram-запросы только при явном запуске; одно копирование проекта его не запускает.

## Обновление и сохранение прогресса

Перед заменой кода сделайте согласованную резервную копию SQLite штатным backup API:

```sh
python3 scripts/backup-db.py --source /var/lib/bziker/game.db --output /var/backups/bziker/game-before-update.db
```

Скрипт читает исходную БД без записи, проверяет копию и отказывается перезаписывать существующий файл. Бэкап хранится отдельно от GitHub. Для переноса с локальной версии используйте такую копию и сохраните права владельца файла. Новый сервер выполняет имеющиеся миграции при старте. Проверку миграции сначала выполняют на копии, затем обновляют рабочую службу. Удаление `data/` из GitHub не означает удаление прогресса на сервере: путь хранения задаётся `--db`.

Для возврата старой версии остановите службу, верните совместимые код и резервную копию БД и запустите её снова. Код и БД рассматривают совместно: миграция новой версии не обязана быть обратно совместимой со старым кодом.

Эти файлы — инструкции и шаблоны. В текущем сеансе домен, токен, сервер и GitHub-репозиторий не подключены; размещение не выполнялось.
