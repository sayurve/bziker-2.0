# Бзикер — передача проекта

Игра запускается из корня этого каталога. Сервер: Python 3.10+ и SQLite из стандартной библиотеки. Клиент: браузерные модули JavaScript, HTML, CSS и готовые PNG. Сборка клиента и платные сервисы для запуска не нужны.

## Что передавать

Создайте отдельный пакет игры, а не репозиторий с родительской папкой «Контент»:

```sh
python3 scripts/package-handoff.py --source-art path/to/Bziker --output ../bziker-handoff --archive ../bziker-handoff.zip
```

Замените `path/to/Bziker` на каталог предоставленного исходного дизайн-пака. Для повторной упаковки уже экспортированной игры этот аргумент не нужен. Папка назначения и архив должны отсутствовать. Скрипт не меняет исходную игру, не подключается к GitHub и не отправляет файлы. В пакет входят сервер, `web/`, `assets/`, тесты, генераторы, документы и 18 эталонных PNG для проверок сохранности исходных материалов. PNG эталонов проверяются по ранее записанным SHA-256. Данные игроков и настройки сервера в пакет не входят.

По умолчанию исторические снимки, PDF и видео из `docs/` и `screenshots/` исключены как дубли доказательств. Текстовые документы и JSON-манифесты остаются. Для полного набора иллюстраций используйте `--include-proof`. Состав, размеры, контрольные суммы и все преобразования переносимости записываются в `handoff-manifest.json`. Отдельный список исключений доступен в этом же файле.

В экспортированной папке нет зависимостей от путей компьютера автора. Три исторических теста оригинальных PNG используют `source-reference/`; их проверки пикселей и SHA-256 сохранены. Импортёры внешнего дизайн-пака получают путь через `BZIKER_SOURCE_DIR`. Каталог `source-reference/` содержит только эталоны для тестов, а не весь внешний дизайн-пак. Повторный полный импорт требует отдельно переданного исходного дизайн-пака. Готовой игре этот пак не требуется.

## Локальный запуск получателем

```sh
cd bziker-handoff
AUTH_MODE=demo HOST=127.0.0.1 python3 server.py --port 8791 --db data/game.db
```

Откройте `http://127.0.0.1:8791/`. Новый файл SQLite создаётся автоматически. Для переноса существующего прогресса оператор передаёт резервную копию БД отдельно от GitHub и запускает сервер с ней. Образец `.env.example` не загружается автоматически: переменные нужно экспортировать или передать через службу запуска.

`AUTH_MODE=account` в текущем сервере отсутствует. `demo` предназначен для локального адреса и поддерживает вход по логину и паролю; сервер запрещает привязку этого режима к публичному интерфейсу. Поддерживаемый публичный режим — `telegram` с `BOT_TOKEN` и HTTPS `PUBLIC_URL`. См. [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверки

Для серверных тестов достаточно Python. Для полного набора JavaScript-тестов нужны Node.js 22+ и локальная зависимость `@napi-rs/canvas`:

```sh
python3 scripts/check-handoff.py
python3 -m unittest discover -s tests -v
npm ci --ignore-scripts
npm test
```

`check-handoff.py` создаёт временную пустую БД, запускает копию сервера на свободном локальном порту, проверяет страницы, все разрешённые статические файлы, новую сессию и отказ в выдаче БД. Он не касается рабочей БД и не выполняет Telegram-запросы. `npm test` добавляет локальный `node_modules` в путь поиска исторических Canvas-тестов; глобальная установка не требуется.

В экспортированную папку добавляется GitHub Actions workflow из `deploy/github-check.yml`: после загрузки он запускает проверку чистого старта и полные Python/JavaScript-тесты с зависимостями из lock-файла. Создание пакета само по себе не запускает облачные задания.

Если ZIP нужен после проверок, сначала запустите упаковщик без `--archive`, затем выполняйте проверки внутри созданной папки. Вернувшись в исходный проект, создайте архив командой `python3 scripts/package-handoff.py --output ../bziker-handoff --finalize --archive ../bziker-handoff.zip`. Финализация сверяет все сохранённые SHA-256 и исключает установленный `node_modules` и `.git`; при изменении файлов после сборки она отказывается создавать архив.

Для повторной генерации/импорта PNG дополнительно нужен Pillow, перечисленный в `requirements-dev.txt`. При обычном запуске и серверных тестах он не нужен. Исторические версии карты сохранены для регрессионных проверок; они не являются отдельной действующей игрой.

## Отдельный репозиторий GitHub

После проверки экспортированной папки можно создать в ней новый локальный репозиторий:

```sh
git init -b main
git add .
git commit -m "Initial Bziker game handoff"
```

Затем владелец подключает свой GitHub и создаёт репозиторий с нужным именем и доступом. Для GitHub CLI после авторизации:

```sh
gh repo create OWNER/bziker --private --source=. --remote=origin --push
```

`OWNER` заменяется на выбранного владельца. Публикация не выполняется упаковщиком. В этом сеансе владелец и имя удалённого репозитория не установлены. Все файлы от 100 МиБ блокируют сборку; внешний дизайн-пак передают отдельно.

## Где продолжать работу

- `server.py`, `auth.py`, `game.py`, `world.py`, `economy.py`, `social.py`, `cards.py`: серверные правила и HTTP.
- `web/app.js`, `web/world.js`, `web/source-*.js`: интерфейс и Canvas-отрисовка.
- `web/world-map.json`, `web/interiors-map.json`, `web/furniture-map.json`: действующая геометрия и предметы.
- `web/design-data.js`, `docs/design-source-v17.json`: происхождение и размеры материалов.
- `tests/`: воспроизводимые регрессионные проверки.
- `docs/bugfix-v24/verification.md` и последующие отчёты: результаты проверок и известные ограничения.

Пакет передачи не подтверждает испытание на физическом телефоне, нагрузку в 100 игроков или успешное публичное размещение. Эти проверки выполняются на целевом устройстве и сервере после выбора среды размещения.
