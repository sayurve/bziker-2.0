# Бзикер — игра с Phaser: запуск и передача

Это папка самой игры. Здесь находятся Python-сервер, браузерный интерфейс,
игровые материалы, тесты и документы. Мир отрисовывается сценой Phaser:
персонажи, предметы, участки земли и остальные объекты создаются отдельно.
Телефон, инвентарь, настройки и игровые окна остаются HTML-интерфейсом.
Phaser включён в `web/vendor/`; для обычного запуска скачивать движок,
собирать JavaScript или устанавливать Node.js не требуется.

Серверные подсистемы аккаунтов, сохранений, экономики, заданий, общения,
кланов, карточных комнат, казино и викторины находятся в том же проекте.
Наличие подсистемы в исходниках само по себе не означает проверку каждого
пользовательского сценария. Результаты проверок нужно смотреть в отчётах
соответствующей сборки.

## Локальный запуск

Нужен Python 3.10 или новее. Сервер использует стандартную библиотеку Python
и SQLite. Выполните команды из этой папки, где лежит `server.py`:

```sh
AUTH_MODE=demo HOST=127.0.0.1 python3 server.py --port 8791 --db data/game.db
```

Откройте `http://127.0.0.1:8791/` на том же компьютере. Файл `data/game.db`
создаётся при запуске. Сервер должен оставаться запущенным. Если порт занят,
выберите другой `--port` и откройте соответствующий адрес.

Команда приведена для macOS/Linux. В PowerShell переменные задаются отдельно:

```powershell
$env:AUTH_MODE = "demo"
$env:HOST = "127.0.0.1"
python server.py --port 8791 --db data/game.db
```

Режим `demo` разрешён для локального интерфейса. Эта команда не создаёт
публичный сервер и не открывает доступ с физического телефона. Для
публичного размещения используйте поддерживаемый режим, описанный ниже.

## Что включено и что передаётся отдельно

- `server.py` и соседние Python-модули — HTTP, аккаунты, игровые правила и БД.
- `web/` — интерфейс, сцена Phaser, обработка управления и анимаций.
- `assets/` — материалы, которые использует игра; копируются целиком из
  выбранных файлов проекта с сохранением текущего содержимого.
- `web/vendor/` — встроенная версия Phaser и её лицензия.
- `tests/`, `scripts/`, `docs/`, `deploy/` — проверки, инструменты,
  документы и шаблоны размещения. Локальные файлы `.log` исключены.
- `source-reference/` — эталонные изображения для исторических проверок.
  Это не весь исходный дизайн-пак.
- `phaser-game-manifest.json` — состав пакета, размеры и SHA-256.

В пакет не входят действующая БД и данные игроков, `.env` с настройками,
токены, каталоги секретов, `.git`, `node_modules`, виртуальные окружения,
кэши и локальные логи. Образец `.env.example` содержит шаблон настройки;
программа не загружает этот файл автоматически.

Для обычного запуска используются включённые `assets/`. Весь исходный
дизайн-пак `Bziker` и соседняя библиотека материалов `Phaser` нужны для
повторного импорта и разработки материалов; их передают дополнительно,
если разработчик будет пересобирать исходные ресурсы. Импортёры получают
путь к исходному дизайн-паку через `BZIKER_SOURCE_DIR`.

Существующий прогресс переносится отдельной согласованной копией SQLite,
а не загрузкой рабочей БД в репозиторий. Команда резервного копирования
и порядок обновления приведены в [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверки получателем

Сначала проверьте чистый запуск с временной пустой БД:

```sh
python3 scripts/check-handoff.py
python3 -m unittest discover -s tests -v
```

Для JavaScript-тестов дополнительно нужны Node.js 22+ и зависимости из
`package-lock.json`:

```sh
npm ci --ignore-scripts
npm test
```

`@napi-rs/canvas` нужен офлайн-тестам и инструментам отрисовки, а не серверу
или клиентскому Phaser. Проверки исходных PNG используют
`source-reference/`. Исторические документы о Canvas относятся к прежней
отрисовке; актуальная сцена описана в
[docs/phaser-migration-plan.md](docs/phaser-migration-plan.md).

После запуска проверьте вход и повторный вход, сохранение прогресса,
движение во всех направлениях, столкновения, двери, интерьеры, действия,
телефон, инвентарь и смену раскладки управления. Отдельно проверьте сцены
с другими игроками, клановую базу и игровые комнаты. Такой список является
инструкцией проверки, а не заявлением, что всё уже проверено получателем.

Проверка в браузере с уменьшенным viewport подтверждает компоновку этого
viewport. Она не заменяет испытание на физическом телефоне: производительность,
касания, звук и работа WebGL проверяются на целевом устройстве. Нагрузочную
проверку нескольких одновременных игроков также выполняют отдельно.

## Публичное размещение

Поддерживаемый публичный режим текущего сервера — `AUTH_MODE=telegram`.
Нужны Telegram-бот, его токен, домен и HTTPS-прокси. `AUTH_MODE=account`
в этом сервере отсутствует. Не публикуйте локальный режим `demo`.

Точная последовательность установки находится в
[DEPLOYMENT.md](DEPLOYMENT.md); шаблоны — в `deploy/`.
Используйте отдельный каталог постоянной БД, один экземпляр сервера с
одной SQLite-БД и настройки вне репозитория. Токен бота задаётся оператором
на целевом сервере. Само копирование этого пакета не запускает бота,
не создаёт домен и не выполняет размещение.

## Где продолжать разработку

Отрисовка Phaser находится в `web/phaser-world-renderer.js` и
`web/phaser-scene-paint.js`; связь сцены с движением и серверным состоянием —
в `web/world.js`. Исходные позы и внешний вид актёров обрабатываются в
`web/source-actors.js`. Модуль `web/locomotion.js` содержит экспериментальный
вариант чередования конечностей; его наличие в пакете не означает, что он
включён или что новые кадры утверждены. Отдельно перерисованные циклы
движения находятся в работе и требуют визуальной приёмки перед подключением.
Точки взаимодействия и серверные ограничения остаются в существующих
Python-модулях и данных карты. Полное описание серверной части и прежнего
процесса передачи сохранено в [HANDOFF.md](HANDOFF.md).

Пакет фиксирует текущие рабочие файлы, включая ещё не закоммиченные изменения.
Упаковщик не создаёт коммит, репозиторий или публикацию в GitHub.
