# Бзикер v7: действия с предметами

Успешное использование настоящего перекуса, кофе, подбор мусора и его выбрасывание теперь создают короткое действие игрока. Эти данные видны самому игроку и находящимся в его комнате участникам. Анимация использует существующую позу: сидящий персонаж сохраняет скамейку и телефон, координаты не меняются.

## Контракт

`action_effect`: `{id,type,started_at,duration,item_id,target_id,x?,y?}`. Длительность — 3 секунды, что даёт четыре последовательные фазы по 0,75 секунды. Типы: `eat`, `drink`, `pick-litter`, `throw-litter`. Кофе создаёт `drink`, перекус — `eat`. Для действий с мусором координаты относятся к проверенному сервером предмету или урне; у еды/кофе цели нет.

`holding`: `litter`, если в настоящем инвентаре есть `trash` с количеством больше нуля, иначе `null`. После окончания подбора мусор остаётся в руке. После выбрасывания последнего предмета он исчезает; если есть ещё мусор, удержание сохраняется.

Оба поля находятся в снимке мира сверху и у каждого видимого игрока. В экономическом ответе поля присутствуют сразу, вместе с `server_time`, поэтому можно показать действие до следующего опроса мира. Существующая двухсекундная система поглаживания `pet_effect` сохранена отдельно.

## Авторитет и хранение

Действие создаётся в одной транзакции с фактическим расходом/получением предмета. Недостаточный инвентарь, неверная цель, слишком большая дистанция, недоступная роль и неподдерживаемое действие не создают эффекта. Переданные клиентом идентификатор или тип не становятся авторитетными: сервер определяет действие сам.

Повтор уже выполненного подбора сохраняет прежний идемпотентный ответ: не добавляет мусор и не создаёт новый идентификатор действия. Даже после окончания эффекта повтор не перезапускает анимацию.

`world_action_effects` хранит не более одной последней записи на аккаунт. Записи создаются только при успешном действии, а не по кадрам или во время чтения. Истёкший эффект возвращается как `null`, без периодических очисток/записей. Координаты, поза, скамейка и состояние телефона остаются прежними.

Эффект и количество мусора добавлены двумя соединениями к существующему общему запросу игроков. Дополнительных запросов для каждого игрока нет. Анонимный куратор получает `action_effect:null`, `holding:null` и пустой список игроков; его данные не попадают в чужой снимок.

## Проверка

- 7 новых Python-тестов: реальные предметы и четыре границы фазы, видимость соседям, сидение/телефон, удержание и выбрасывание, ошибки и подделки, идемпотентный подбор, перезапуск/истечение без записей, права куратора и валидация внутреннего типа.
- Все 206 Python-тестов прошли после реализации. Отдельный повтор нового набора после усиления проверки повтора подбора также прошёл.
- Эталонный снимок v6 не переписан. Удаляются только явно новые поля сверху и у игроков; всё остальное сравнивается с прежним эталоном. Новые поля проверяются отдельно.
- Проверка 100 игроков содержит действующие эффекты, реальные питомцы и мусор. Она подтверждает единственность строк игроков и постоянный лимит запросов.
- HTTP-нагрузка на временной базе: 100 профилей, 8 одновременных рабочих потоков, 200 успешных запросов из 200. Один снимок — 30 SQL-команд и одна запись текущей позиции; добавление эффектов не увеличило количество SQL-запросов относительно версии с гуляющими животными. Продолжительность 200 запросов — 1,386 с; p95 — 212,65 мс; p99 — 782,26 мс. Это измерение на текущем компьютере, не испытание 100 телефонов.

Измерения: `docs/action-effects-v7-load.json`. Проверки: `python3 -m unittest discover -s tests`; `python3 -m unittest discover -s tests -p 'test_action_effects_v7.py'`; `python3 tests/benchmark_backend_v6.py .`.
