# Бзикер 2.0 — передача разработчику через GitHub

Репозиторий кода: [sayurve/bziker-2.0](https://github.com/sayurve/bziker-2.0). Материалы опубликованы в [release v2.0](https://github.com/sayurve/bziker-2.0/releases/tag/v2.0); размеры и SHA-256 всех восьми вложений проверены по данным GitHub. Порядок загрузки шести частей и проверки SHA — [MATERIALS_RELEASE.md](MATERIALS_RELEASE.md).

Начните с [корневого README](../README.md). Эта инструкция относится к **проекту 2.0 целиком**: в его корне находятся `game/`, `tools/`, `docs/`, `.agents/`, `art/` и `verification/`. Работайте в полученной копии 2.0; соседний исходный `Bziker` для запуска не нужен и не изменяется. GitHub хранит исходники; загрузка репозитория сама по себе не публикует работающую игру.

## Первый запуск

Нужны Python 3.10+ и современный браузер. Сервер использует стандартную библиотеку Python и SQLite. Локальный **Phaser 4.2.1** уже включён в `game/web/vendor/`; для игры не нужны Node, сборка клиента, CDN или платные сервисы.

Откройте терминал в корне полученной папки 2.0, где находится этот README, и выполните:

```sh
python3 tools/run.py --demo --port 8796
```

Откройте <http://127.0.0.1:8796/>. Лаборатория персонажа: <http://127.0.0.1:8796/character-lab>. Сервер должен оставаться запущенным; остановка — `Ctrl+C`. На macOS также есть `Запустить Бзикер.command`. Если порт занят, выберите другой `--port` и тот же порт в адресе браузера.

Новая локальная БД создаётся автоматически в **`data/bziker.db` корня 2.0**. Другая отдельная БД задаётся аргументом `--db`; существующие данные не требуются. Данные игроков и рабочая БД автора в публичную передачу не входят. При прямом запуске `game/server.py` без помощника применяется другой default — `game/data/game.db`; для разработки 2.0 используйте команду выше, чтобы не перепутать сохранения.

## Окружение и проверки

Для инструментов и JavaScript-тестов нужен **Node.js 22+**. Установите закреплённую Canvas-зависимость из `game/package-lock.json`:

```sh
cd game
npm ci --ignore-scripts
cd ..
python3 tools/check-project.py --quick
python3 tools/check-project.py --full
python3 game/scripts/check-handoff.py
```

`--quick` проверяет проектные инструменты и новую систему персонажа; `--full` запускает также все Python/Node-тесты игры. Handoff-проверка поднимает сервер с временной пустой БД и проверяет статические маршруты и чистый старт. Она не использует рабочую БД. Отчёты сохраняются в `verification/`. Если требуется выбрать конкретный Node для помощника, задайте путь в `BZIKER_NODE`.

Pillow из `game/requirements-dev.txt` нужен для импорта/пересборки изображений, а не для обычного сервера. Не переимпортируйте материалы ради первого запуска. `materials/Bziker/` — отдельная большая библиотека и исключена корневым `.gitignore`; её можно восстановить из [release по инструкции](MATERIALS_RELEASE.md); импортёры принимают `BZIKER_SOURCE_DIR`. Готовая игра использует включённые runtime-ресурсы `game/assets/` и локальный `game/web/vendor/`.

**Не сокращайте репозиторий до одной `game/` при передаче всей 2.0.** Новые тесты используют также конкретные `art/` и `verification/` fixtures: например, `game/tests/h7-orphan-scalp-v30.test.mjs` читает `verification/hair-tint-v30/h7-left-islands-before.png`. Сохраняйте эти зависимости и `game/source-reference/`. Старый game-only экспорт из [game/HANDOFF.md](../game/HANDOFF.md) — отдельный формат, не замена корню 2.0 и его полному регрессу.

## Настройки сервера

Образец — [game/.env.example](../game/.env.example). Python **не загружает `.env` автоматически**: переменные задаются окружением процесса или службой запуска. Локальная команда `--demo` не требует токенов и привязывает сервер к `127.0.0.1`.

Для публичной игры поддержан `AUTH_MODE=telegram`, нужны `BOT_TOKEN` и HTTPS `PUBLIC_URL`; режима `AUTH_MODE=account` нет. Настройки оператора и токен хранятся вне Git, БД — в отдельном постоянном каталоге. Точная установка, резервное копирование и обновление — [game/DEPLOYMENT.md](../game/DEPLOYMENT.md). Страница GitHub и localhost не являются HTTPS-размещением игры для физического телефона.

## Где продолжать разработку

Сначала прочитайте [AGENTS.md](../AGENTS.md), [архитектуру](ARCHITECTURE.md), [актуальный статус](STATUS.md) и [план](IMPLEMENTATION_PLAN.md). Для работы через Codex проект содержит навыки профиля В: [SKILLS.md](SKILLS.md).

| Задача | Основные файлы |
| --- | --- |
| HTTP, аккаунты, сохранения и серверные правила | `game/server.py`, `game/auth.py`, `game/game.py`, `game/world.py`, `game/economy.py` |
| Управление, телефон, инвентарь и окна | `game/web/app.js`, `game/web/avatar.js` |
| Мир, движения, взаимодействия и отправка на сервер | `game/web/world.js` |
| Phaser-отрисовка и камера | `game/web/phaser-world-renderer.js`, `game/web/world-camera.js` |
| Позы, голова, материалы волос/кожи/одежды и предмет в руке | `game/web/source-actors.js`, `game/web/actor-sprite.js` |
| Текущие цельные C/L/A-позы | `game/web/canonical-actors-data.js`, `game/web/locomotion-actors-data.js`, `game/web/interaction-actors-data.js` |
| Новый контракт послойного персонажа | `game/web/character-system/`, `game/web/character-lab.js` |
| Геометрия и генераторы интерьеров | `game/web/interiors-map.json`, `game/scripts/build-modular-interiors.py`, `game/scripts/interior_plans/` |

Кошелёк, покупки, права, движение и действия подтверждает сервер. Рисунок/анимация не выдаёт предметы и деньги самостоятельно. Для исправления сначала сохраните воспроизводимый сценарий, затем проверьте затронутую логику и реальную игру. Геометрия интерьеров читается сервером при старте: после её регенерации нужен перезапуск. Кадры персонажа не подгоняются по bbox; у одежды требуется полное покрытие поз, единая опора и фаза. Исходники PNG, авторские anchors и происхождение экспортов сохраняются.
