Здесь есть рабочая игра, проектные навыки, новый контроллер поз/одежды и проверки; полная библиотека материалов восстанавливается отдельно из release. Новая послойная графика ещё требует редактируемых мастеров и художественной приёмки; техническая сборка не подменяет этот этап.

## Запуск

Дважды нажмите `Запустить Бзикер.command` либо из этой папки выполните:

```sh
python3 tools/run.py --demo --port 8796
```

Игра: http://127.0.0.1:8796/ . Лаборатория персонажа: http://127.0.0.1:8796/character-lab . Нужен Python 3.10+. Серверные зависимости — стандартная библиотека. Движок Phaser закреплён локально, Node для запуска самой игры не требуется.

Новая пользовательская БД создаётся в `data/bziker.db`; старая БД не переносилась. Для сервера/Telegram прочитайте `game/DEPLOYMENT.md`: нужен HTTPS и соответствующая авторизация. Локальный адрес не является опубликованной игрой для телефона.

## Что где находится

- `game/` — работающая игра с аккаунтами, сохранениями, городом, интерьерными переходами, кланами, магазинами, телефоном, инвентарём и мини-играми текущей версии.
- `game/web/character-system/` — новый контракт моделей/одежды, общий контроллер фаз, атомарный Phaser view и загрузчик полных PNG-слоёв.
- `materials/Bziker/` — самостоятельная библиотека исходных материалов и подготовленного Phaser-каталога после [восстановления из release](docs/MATERIALS_RELEASE.md); проверяется без соседней папки.
- `art/drafts/` — неодобренные новые изображения. `art/approved/` — место только для реально проверенных мастеров/экспортов.
- `.agents/skills/` — три навыка: `$bziker-build-game`, `$bziker-character-pipeline`, `$bziker-game-qa`. Правила и включение — `docs/SKILLS.md`.
- `docs/ARCHITECTURE.md` — принятая архитектура; `docs/STATUS.md` и `docs/IMPLEMENTATION_PLAN.md` — состояние реализации; `verification/` — фактические отчёты.

## Проверки

```sh
python3 tools/check-project.py --quick
python3 tools/check-project.py --full
```

Node >=22 нужен только для инструментов и тестов. На другом компьютере сначала выполните `npm ci` в `game/` для закреплённой зависимости Canvas. При наличии среды Codex проверка может использовать её Node; собственный путь задаётся через `BZIKER_NODE`.

Библиотека материалов не входит в Git-клон и не нужна для этих двух команд. Дополнительная `python3 tools/verify-materials.py --dest .` применяется только после полного [восстановления из release](docs/MATERIALS_RELEASE.md), включая его манифест.

`--quick` проверяет инструменты и новую систему персонажа; `--full` дополнительно запускает все серверные и игровые тесты. `--materials` у check-project добавляет полную сверку SHA-256 библиотеки; `verify-materials.py` запускайте после [восстановления материалов](docs/MATERIALS_RELEASE.md). В отчётах отдельно показывается незавершённый арт. Успешная загрузка PNG не означает, что лицо, одежда и походка одобрены.

## Правильный порядок работы с персонажами

Согласованный редактируемый мастер → позы четырёх направлений → настоящие слои одежды на тех же позах → отдельные PNG без подгонки по силуэту → проверка покрытия и размера → просмотр в Phaser → подключение проверенного комплекта. Один контроллер выдаёт poseKey всем слоям. Смена одежды сохраняет фазу, опору и масштаб; неполный комплект оставляет предыдущий целым.

Старые цельные позы в игре и лаборатории обозначены `legacy-composite`. Это честный режим совместимости: он сохраняет существующую игру, но не объявляется новой послойной моделью. Сгенерированные независимо PNG с дрейфом головы не подключены как готовые.

## Передача

Передавайте всю папку `Bzikert 2.0`; ссылки на исходный соседний каталог для запуска не нужны. Игровая папка достаточна для обычного запуска, библиотека материалов нужна разработчику и художнику. Не включайте созданную позже пользовательскую `data/` в публичную передачу. Код передаётся через [репозиторий 2.0](https://github.com/sayurve/bziker-2.0); публикация материалов release v2.0 ещё выполняется. Это передача исходников, а не размещение публичного игрового сервера.
