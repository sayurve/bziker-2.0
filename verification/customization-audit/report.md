# Независимый аудит каталога внешности и источников ходьбы

Профиль В. Runtime, исходная библиотека и браузер этим агентом не изменялись. Браузер на 8797 ведёт основной агент; волосы исправляет отдельный агент, движение — core. Это исходный аудит и пакетный инструмент, а не художественная приёмка после чужих правок.

## Реальный UI и доступность

Прочитаны `game/web/app.js`, `profile-builder.js`, `avatar.js`, `source-actors.js`, `actor-sprite.js`, `city-features.js`, `inventory-ui.js`; серверные `game.py` и `economy.py`. Три вкладки: «Волосы», «Одежда», «Детали»; пол выбирается отдельно. Всего **12 параметров, 84 значения: 78 бесплатных, 6 покупаемых костюмов**. Это число отдельных значений каталога, а не число сочетаний.

Причёски: короткая, каре, кудри, пучок, ёжик, пробор, длинные, хвост, пикси, ирокез, два пучка, волны. Все 12 доступны обоим полам. Верх: футболка/худи/куртка/рубашка. Низ: прямые брюки/шорты/юбка/широкие брюки. Головные уборы: без убора/кепка/шапка/панама/берет. `accessory=3` тоже обозначает кепку; `headwear` имеет приоритет перед этим fallback.

Шесть бесплатных пресетов используют `outfit=0`, не обходят покупку костюмов. Костюмы `outfit-1..6` стоят соответственно **100,140,180,120,200,160 Бзинге**: хромовая куртка, неон-худи, креативное пальто, спортивный костюм, костюм зверя, дождевик. Без ownership UI ставит `disabled`; сервер `GameService.profile` проверяет inventory и возвращает `outfit_locked`, HTTP403. Просто отправить индекс или снять disabled недостаточно для законного применения. Изменять баланс/ownership QA-аккаунта этому аудиту не требовалось; покупок и сохранения платных костюмов не выполнялось. Отрисовка их отключённых миниатюр допустима как существующий UI preview, не как обход авторизации.

## Preview и мир — действительные разные пути

Главный `avatarPreviewHTML` вызывает `avatarSVG` с выбранным facing, без walking. Каталожная `hairStyle` миниатюра снимает headwear/outfit/accessory и вызывает `headOnly`; headwear использует `face:false,headOnly:true`. Миниатюры shirtStyle/pantsStyle снимают outfit. Палитры показывают SVG-плашки, а не отдельную полноразмерную позу.

`avatarSVG` получает настоящий `avatarRaster` и рисует его coarse runs. Мир вызывает `drawAvatarCanvas` → `drawSourceAvatarCanvas` и при наличии использует detail/fine bitmap с сохранёнными native pixels. Поэтому скрипт рисует **две картинки рядом: coarse UI raster слева, настоящий fine world canvas справа**; это не два независимых вымышленных mockup.

В исходном snapshot male idle приходит из canonical-idle-male-{direction}; female down — legacy01_На_месте, female right/up/left — legacy walk frame0. То есть остановленная женская модель сбоку уже наследует stride-позу. Это подтверждено записанными frame.id в metrics, а не предположением о кнопке движения. Core-агенту передано; этот отчёт не объявляет исправленным последующее состояние.

## Воспроизведение batch QA

Из корня:

```sh
/Users/sapp/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node verification/customization-audit/render-options.mjs final
```

Скрипт принимает только имя нового запуска из латинских букв/цифр/дефисов, сохраняет всё в соседнюю подпапку. Можно использовать любой Node, которому доступен установленный `@napi-rs/canvas`. Не запускает сервер, не открывает браузер, не пишет runtime или материалы.

Загружаются настоящие native файлы через loadSourceActor. Метрики включают SHA исходного кода до/после; `sourceFilesStable=false` делает процесс неуспешным и требует повторного прогона после freeze. После чужих изменений нужно получить новый запуск, а не использовать initial как окончательное доказательство.

`initial/metrics.json`: **608 idle cases** =76 бесплатных значений, кроме отдельной оси пола, ×2пола×4направления; из них96hair. **384hair walk cases** =2×12×4×4фазы. Непустые992/992, fallback0; шесть outfit disabled. 18PNG: полные листы всех бесплатных значений, отдельные24head-only previews и9настоящих iconSVG инвентаря. Все 18initial PNG просмотрены через view_image. Все 12 hair/4 shirt/4 pants/5 headwear/6 accessory/8skin дают разные хеши для каждого пола/вида; это не доказательство корректности рисунка.

Расширенный текущий скрипт дополнительно покрывает **все бесплатные параметры во всех четырёх фазах ходьбы: 608×4=2432** cases, включая прежние384hair. `coverage/metrics.json` подтвердил608/608idle и2432/2432walking непустыхcases, fallback0, stable=true. Исходные SHA вinitial иcoverage совпали. Эти walking cases измеряются и хешируются; не каждый визуально просматривается отдельно. Инвентарная HTML-разметка получена настоящим inventoryHTML, контакт — настоящим itemIconSVG. Размещение CSS инвентаря этим offscreen canvas не проверяется.

## Подтверждённые исходные визуальные замечания

1. Initial hairStyle/contact и hair-catalog-heads показывают остатки исходных волос и наложение новых контуров/полос около лица, особенно на female. Непустая/уникальная картинка не означает готовую причёску. Дефект передан отдельному hair-агенту; повторная приёмка нужна после его freeze.
2. Initial `pantsStyle=2` («Юбка») выглядит как горизонтальные полосы с разрывами в нижней части тела в обоих полах/четырёх видах. Код customize использует фиксированные ряды44..54 с повторением `44+(y-44)%6`, включая прозрачные клетки исходника; это воспроизводимый источник полос. Код этого аудита не исправлял.
3. Женский static side idle выбирает walk frame0, что объясняет широкую постановку ног после остановки. Настоящий исправленный idle не появляется лишь от наличия draft файла.

## Альтернативные исходники ходьбы

Просмотрены оба полных `materials/Bziker/02_Персонажи/{Мужчина,Женщина}/Анимации/00_Исходники/Лист_циклов.png`, левосторонние фазы и `06_Повседневные_действия/00_Исходники/Слои/{пол}/Ходьба_right.png`. Прочитаны prompt и source provenance мужского cycle sheet.

- У обоих полов стандартная Ходьба содержит4unique phases из24файлов/2секунд. Right=исходные cells4..7; front0..3; back8..11. ExportLeft зеркалит Right (`mirrored:true`, `phase_mirrors` всеtrue).
- В самих полных исходных листах **row2,col5..8 / zero-basedcells12..15** есть отдельные нарисованные LEFTwalk. Это реальная альтернативная левая четвёрка, не использованная metadata экспортомLeft. Она немедленно сообщена core/root. Привязки, лицо и опорную стопу нужно проверить до production; готовность не объявлена.
- Daily `Ходьба_right.png` — только вырезанный нижний слой той же широко расставленной позы; это не независимый новый полнотелый grounded cycle.
- В просмотренных исходных листах ходьбы не подтверждён качественный полный четырёхнаправленный цикл с контактной и проходящей фазой, подходящий для автоматической замены. Просмотр не охватывает каждый архив/каждый файл библиотеки. Отсутствие подходящего варианта во всей библиотеке не заявляется.

Канон идентичности остаётся первыми двумя run screenshots в art/references/canonical-run; старый третий idle исключён. Новое одобрение арта, browser coverage, телефон и сохранение всей одежды в любых действиях этим аудитом не подтверждены.
