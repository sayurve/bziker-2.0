Для проверки установлен PyYAML 6.0.3 только в `/tmp/bziker-skills-validator-deps` и передан через `PYTHONPATH`; глобальные пакеты не менялись. Bundled Python найден через `load_workspace_dependencies`. Повторная валидация каждой папки завершилась exit 0 и `Skill is valid!`.

Дополнительно проверены все семь файлов навыков/инструкции активации на остатки TODO-заготовок и жёстко заданные пользовательские абсолютные пути: таких остатков нет. Повторный запуск штатного валидатора после содержательных правок также дал exit 0 для трёх навыков. Программная проверка metadata подтвердила длины short_description 25–64 символа, `$skill-name` в каждом default_prompt и разрешённую по умолчанию implicit invocation; общий exit 0. Ссылки на контракт и команды исходной игры сверены с существующими файлами, включая `game/web/character-system/README.md` и `definition.js`. По согласованному интеграционному контракту корневого агента в инструкции внесены `python3 tools/run.py --port 8796 --demo`, `python3 tools/check-project.py --quick`, `--full`, `--materials` и самостоятельный `python3 tools/verify-materials.py --dest .`. Лаборатория — `/character-lab`; загрузчик — `game/web/character-system/asset-loader.js`, с обязательным artReview для approved-ресурсов. Рабочие режимы этих новых helper-команд внедряет и проверяет интеграционный этап; этап навыков запустил только справочные --help, как указано ниже. Сравнение копии по manifest не объявляется подтверждением неизменности недоступного внешнего исходника. Инструкции используют относительные пути проекта.

## Содержательная сверка

- Сборка сохраняет Phaser/Python, работающие подсистемы и отдельность исходника, авторитет сервера для кошельков/прав, мобильное управление, 10 слотов и отдельный телефон.
- Pipeline требует canonical editable master, общие голову/лицо/палитру, фиксированные холст/опору, реальные слои и полный PNG отдельно, покрытие всех поз каждым слотом, порядок по направлениям, точки кистей/посадки, один snapshot/clock и атомарное надевание.
- Независимая генерация изображения не доказывает идентичность лица. Сдвиги прямоугольников/зеркалирование не признаются исправлением походки. `legacy-composite` не выдаётся за новые послойные исходники.
- QA требует реальные exit codes, логи и наблюдение движения/интерьеров/телефона/инвентаря/одежды. Отсутствие runtime, браузера, арта или телефона обозначается как невыполненная проверка. Целостность ресурсов не означает художественного одобрения; драфты сохраняют статус драфта.
- Навыки не создают автоматического разрешения на публикацию, внешние сообщения, реальные платежи или одобрение арта.

Это содержательная проверка написанных инструкций, а не исполнение всех будущих сценариев. Игровые тесты, браузер и физический телефон в рамках этого этапа создания навыков не запускались; их результаты должны быть подтверждены отдельным этапом проекта.


## Независимый сценарный forward-test

Проверяющий агент `bziker2_character_core` прочитал два навыка без изменения файлов, исполнения игры и подсказки ожидаемого решения. Переданы только сами инструкции и два пользовательских запроса.

1. **«Добавь куртку, но кадра сидя нет».** Проверяющий сначала сверяет фактический список поддерживаемых поз модели. Если модель поддерживает сидение, комплект с отсутствующим сидячим кадром отклоняется до надевания, прежний комплект сохраняется целиком. Отсутствующий реальный слой готовится по мастеру в drafts; нельзя подменить его полной фигурой или удалить поддерживаемое сидение ради прохождения проверки. Основание — требование полного покрытия поз и `setOutfit(outfit, view)` с предварительной проверкой всех текстур. Результат инструкции: **ожидаемое поведение получено**.
2. **«PNG загружаются без ошибок — весь визуал готов?»** Проверяющий подтверждает только успешную загрузку, отделяя её от художественного просмотра, браузерных сценариев и физического телефона. Требует сверить лицо, пропорции, направления, походку, перекрытия, опору и свидетельство художественного просмотра. `legacy-composite` не считается новой послойной моделью. Результат инструкции: **необоснованного утверждения о готовности нет**.

Это независимая проверка решений, которые вызывает текст навыков. Она не является запуском визуальных сценариев и не подтверждает качество PNG.

## Финальный read-only аудит команд и API

Реально прочитаны `tools/run.py`, `tools/check-project.py`, `tools/verify-materials.py`, `tools/import-materials.py`, `game/scripts/test-node.mjs`, `game/package.json`, CLI `game/server.py`, а также `definition.js`, `controller.js`, `phaser-view.js` и `asset-loader.js`.

Из корня выполнены только справочные вызовы `python3 tools/run.py --help`, `python3 tools/check-project.py --help`, `python3 tools/verify-materials.py --help`, `python3 tools/import-materials.py --help`: каждый **exit 0**. Игру, импорт, полный хеш материалов, установку и игровые тесты этот аудит не запускал.

- `run.py` реально принимает `--port`, `--demo`, `--db`, задаёт `HOST=127.0.0.1` и запускает `game/server.py`. Для QA в навыке уточнена отдельная `--db verification/qa.sqlite3`; существующий файл не переиспользуется без проверки назначения.
- `check-project.py` реально принимает `--quick`, `--full`, `--materials`. Без `--full` выполняются root Python tool tests и character-system Node tests; с `--full` — root tool tests и вся игра Python/Node. `--materials` дополнительно вызывает standalone verify-materials.
- `verify-materials.py --dest .` не требует source, сверяет копию по manifest и выставляет `source_comparison_performed: false`, `source_unchanged: null`, если внешний источник не указан. Навык это различие сохраняет. Импортёр требует source/dest и отказывается от непустого назначения.
- `node scripts/test-node.mjs` и `npm ci --ignore-scripts` соответствуют фактическим `game/package.json`/`package-lock.json`; Node >=22 указан в engines. Python CLI `python3 -m unittest discover -s tests -v` использует реальные тестовые папки; game server принимает port/db и AUTH_MODE/HOST.
- `model.layers`/`outfit.layers`, `layerOrder`, pose keys, `setState`, `advance`, `stop`, `teleport`, `setOutfit(outfit, view)`, `preflightOutfit` и `apply` существуют в текущем API. Загрузчик экспортирует `loadCharacterBundle(scene, bundle, {assetRoot, allowDraft})`, использует schema `bziker-character-bundle/v1`, `definition`, `outfits`, `textures` и проверяет `artReview.checked`/`artReview.evidence` для production. Навыки не предписывают несуществующее поле slots.
- Все перечисленные базовые документы, пути игры, scripts и модули персонажа присутствуют. Первоначальное замечание о лаборатории **закрыто после повторной read-only проверки**: существуют `game/web/character-lab.html`, `game/web/character-lab.js` и `game/web/character-lab.css`; `game/server.py` явно задаёт `STATIC['/character-lab']='web/character-lab.html'`, а цикл для трёх lab-файлов регистрирует корневые и `/web/` aliases. HTML ссылается на существующие CSS, JS и закреплённый локальный Phaser. JS импортирует реальные CharacterController и PhaserCharacterView и прямо обозначает модели как draft/legacy-composite. Поэтому пути и endpoint, указанные в навыках, соответствуют текущему исходному коду. Повторная проверка наличия и маршрутов не является браузерным тестом или художественной приёмкой.

Итог этапа навыков: три валидных проектных инструкции, подтверждённая регистрация, два независимых корректных сценарных решения и сверенные реальные команды/API/пути. Открытых замечаний к созданным навыкам и их ссылкам по результатам этого аудита нет. Художественное качество PNG, работа браузерных сценариев и физического телефона этим этапом не подтверждались; завершение всей игры не заявляется.
